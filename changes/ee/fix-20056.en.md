Fixed shared subscription members that stayed in the cluster after their node had left it, with the default routing schema (v3). Messages to the shared subscription group could still be dispatched to these members, and these messages were lost. Core nodes now remove the members of a replicant node that is down for 15 minutes, and the members of a node that has left the cluster, as they already did with routing schema v2. Until a member is removed, a node does not dispatch messages to it when its node is not a running cluster member. After the upgrade, members left over from before are removed in the same way.

On a version without this fix, remove such members manually. On a core node, list the nodes that own shared subscription members but are not running:

```
emqx eval "lists:usort(ets:select(emqx_shared_subscription, [{{'_', '_', '_', '\$1'}, [], [{node, '\$1'}]}])) -- mria:running_nodes()."
```

Then, for each node in the list, remove its members:

```
emqx eval "emqx_shared_sub:purge_node('emqx@departed-node')."
```
